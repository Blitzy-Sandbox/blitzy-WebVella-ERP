3. **[High]** **Capture generated admin password at first run for fresh deployments** — the `Console.WriteLine` banner at `ERPService.cs:498-508` emits the 192-bit-entropy password exactly once during system entity initialization. 5. **[Medium]** **Externalize ConnectionString password** — the F-007 finding (High severity, documented but not remediated per AAP scope) recommends moving the database password from `Config.json` plaintext to an environment variable or secrets manager. Estimated: 1 hour.

To complete the path to production, operators must execute the following sequence:

1. **Generate strong secrets** (1.5h): Generate cryptographically strong values for `Settings__Jwt__Key` (≥64 chars high-entropy random data) and `Settings__EncryptionKey` (64 hex chars random). 2. **Configure CORS for production** (0.5h): Update `Settings:Cors:AllowedOrigins` array in production `Config.json` (or set via env var) with the actual production hostnames. The default value (`["http://localhost:5000"]`) works only for local development.

3. **Externalize ConnectionString password** (0.5h): Move the `User Id=dev;Password=dev` plaintext from `Config.json` to an environment variable or secrets manager (Azure Key Vault, AWS Secrets Manager, HashiCorp Vault).

4. **Rotate pre-seeded admin password** (1h): For databases seeded BEFORE the F-003 wiring landed (commit `4bfc0a0f`), the admin password remains the legacy `erp` value (transparently PBKDF2-rehashed by F-002 on first login). For fresh deployments, capture the generated 192-bit-entropy password from the `Console.WriteLine` banner at `ERPService.cs:498-508` at first run before logs rotate.

5. **Production smoke test** (0.5h): Validate end-to-end login flow, JWT issuance endpoint, and dashboard render with reverse-proxy HTTPS termination active (so `Cookie.SecurePolicy = SameAsRequest` correctly sets the `Secure` flag).

### 9.8 Troubleshooting

| Symptom | Cause | Resolution |
|---|---|---|
| Application exits immediately with `InvalidOperationException: Settings:Jwt:Key must be overridden...` | F-001 startup validator rejecting default placeholder key | Set environment variable: `export Settings__Jwt__Key="<≥32-byte high-entropy random string>"`; re-run `dotnet run` |
| `dotnet build` fails with `Could not find file '...WebVella.ERP/WebVella.Erp.csproj'` (case mismatch) | Linux is case-sensitive; ProjectReference paths used `WebVella.ERP\` | Already fixed in commit `66ccd45c` — pull latest branch `blitzy-aedda255-c17e-4a48-861b-cec3fd26bf97` |
| `pg_isready` exits 1 / "no response" | PostgreSQL not running | `sudo systemctl start postgresql` (Linux) or start the PostgreSQL service (Windows) |
| Login form returns HTTP 400 Bad Request on POST | Missing or invalid antiforgery token | The login form requires `__RequestVerificationToken` — extract from GET `/login` response and include in POST body |
| Login returns HTTP 200 with "Invalid username or password" for the seed admin | Pre-existing DB seeded BEFORE F-003 wiring, or password was rotated | Try legacy `erp` for pre-existing `ttg_test`-style DBs; for fresh DBs, capture the password from console at first run |
| `dotnet test` reports "No test source files were specified" | No test projects in baseline (per AAP §6.6) | This is expected; per AAP §0.9.3, `dotnet build` is the substitute regression gate |
| 41 build warnings (NU1903 AutoMapper, NU1902 MailKit/MimeKit, ASPDEPR008 IWebHost) | Pre-existing NuGet vulnerabilities; AAP audit-only constraint prevents upgrade | These are documented in F-018, F-019, F-020 of `pentest-findings.md`; remediation requires lifting the audit-only constraint in a future engagement |
| F-005 binder rejects a legitimate type with `JsonSerializationException` | Type's namespace is outside `WebVella.Erp.*` allowlist | Either prefix the type's namespace with `WebVella.Erp.` (legitimate first-party type) OR use `TypeNameHandling.None` with concrete root type at that call site |
